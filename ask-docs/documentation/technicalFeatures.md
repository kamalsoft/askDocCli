# Technical Features & Capabilities

Ask-Docs provides a sophisticated RAG (Retrieval-Augmented Generation) pipeline optimized for local-first performance and privacy.

## 1. Hybrid Inference Orchestration
The application supports three primary modes of reasoning:
-   **Local (Strictly Private)**: Executes Small Language Models (SLMs) like Llama 3.2 1B or Phi 3.5 Mini directly on your CPU via ONNX Runtime.
-   **OpenRouter (Cloud Scale)**: Tunnels reasoning requests to high-parameter models (e.g., NVIDIA Nemotron 120B) via the OpenRouter gateway.
-   **Auto (Intelligent Fallback)**: Attempts cloud reasoning first for maximum accuracy, but automatically fails over to local models if the API is unreachable, rate-limited, or if the API key is missing.

## 2. Agentic RAG Loop
Unlike traditional single-pass RAG systems, Ask-Docs implements an autonomous reasoning loop:
-   **Metacognition**: The model analyzes its own context. If it detects it is looking at an index or a summary (e.g., `index.md`), it can trigger a new search.
-   **Tool Use**: The reasoning engine can output `<search>refined query</search>` tags.
-   **Iterative Enrichment**: The system intercepts these tags, performs a secondary vector/BM25 search, enriches the prompt with new data, and re-runs the synthesis. It supports up to 2 additional search iterations per query.

## 3. Hybrid Search Engine
To solve the "technical acronym" problem inherent in semantic-only models, Ask-Docs uses a multi-stage scoring algorithm:
-   **Vector Similarity**: Uses Jina Embeddings v2 to capture the semantic intent of the query.
-   **BM25 Keyword Scoring**: Uses Inverse Document Frequency (IDF) to weight exact matches for rare technical terms (e.g., `HMAC`, `PCI-DSS`).
-   **Score Fusion**: Combines scores using a calibrated weight (`vScore + bm25 * 0.05`) to ensure exact keyword matches "nudge" relevant documents to the top.

## 4. Performance & Efficiency
-   **Pre-calculated Statistics**: BM25 corpus stats are calculated once during ingestion and persisted in `docs.json`, enabling sub-millisecond retrieval latency.
-   **Quantized Inference**: Supports 4-bit (q4) quantized models, reducing RAM usage by ~70% while maintaining high accuracy on standard CPUs.
-   **Threading Optimization**: Exposes ONNX intra-op threading settings to allow the app to utilize all available CPU cores without causing thermal throttling.
-   **BM25-Only Mode**: A special ultra-fast mode that skips the embedding model entirely, reducing startup time and memory footprint by over 100MB.

## 5. Observability & Diagnostics
-   **Real-time SSE Streaming**: Both the Web UI and Terminal UI (TUI) support Server-Sent Events, showing the AI's internal "Thought Process" and "Agent Status" live.
-   **Verification Suite**: `verify-models.js` provides deep-level integrity checks for ONNX split-weights and API connectivity.
-   **Benchmarking Suite**: A ground-truth validation tool that measures RAG accuracy and confidence scores against a fixed dataset in `benchmarks.json`.

## 6. Configuration Guidance

### Confidence Threshold
The `confidenceThreshold` (set in `ask-docs.config.json`) determines when the system ignores local documents and relies on the LLM's general knowledge.
-   **0.12 (Default)**: Very safe; allows for "fuzzy" semantic matches.
-   **0.30 - 0.50**: High precision; recommended for dense technical manuals.
-   **1.0**: Experimental; only retrieves documents with perfect keyword and semantic alignment.
